# 042 详细魔法街区契约 0.1.1-style042

此为一个受限、独立的 64m 街区入口：[实现](../../src/world_builder/agents/style_scene.py)、[运行工具](../../tools/run_style_042.py)。默认 0.1.0 A—F 与 041 壳体不切换。029 通用场景任务图尚未由本实现完成。

## 模型与本地的职责

调用方固定首例需求为两栋住宅、两栋两层商铺、一座带喷泉/长椅/灯/树木的广场。D 将本例的类型、布局和场景意图一次表达；E 每个场地提出建筑/广场参数；F 读取实际构件与源路线报告审查。这里没有宣称 A/B/C 各有独立模型调用，也没有让旧规则规划器补写整场景。

D 使用 [布局参数 Schema](../../schemas/style042-layout-parameters-0.1.1.schema.json)：道路南缘和宽度；每个场地的类型、街道北/南侧、X 起点、宽、深。道路固定沿 X 向、跨度 x=2..62；本地根据参数计算 Y 包络和朝向道路的入口，记录原文/投影和哈希。数量、场地间距、区域与正尺寸仍受检。相比 v1 的原始矩形提案，这消除了模型重复计算矩形边缘和门朝向的机会。

E 使用 [建筑 Schema](../../schemas/style042-building-0.1.0.schema.json) 或 [广场 Schema](../../schemas/style042-plaza-0.1.0.schema.json)。模型决定楼层、层高、屋顶形态/高度与材料、墙材料、逐层两间房的用途，或广场家具数量。已验证的 `design_building` 和详细 `_building_shell` 执行这些参数；底层策略补出确切门窗、门廊、楼板、家具和楼梯。参数来源与本地策略版本 `legacy-detail-042.1` 明确留证。

旧 Minecraft 构件函数返回 Minecraft 轴向盒体，本入口显式逆变换为 WIR `(东,北,上)` 的米单位细尺寸盒体。其后写入 WIR 的物理几何即为实际导出的细节；Unity GLB 不另造一份建筑。旧“后画的材料覆盖墙面”策略通过几何裁切实现为互不重叠的盒体，保留玻璃/窗框占据的最终体积，避免 Unity 的共面闪烁或玻璃仍被实墙封住。

## 验收边界

源端检查对象覆盖、临街入口、场地间距、详细设计包络、楼层/房间和构件存在性。支持/净空路线以 0.1m 采样构建，胶囊半径 0.30m、高 1.8m、单步高差不超过 0.251m。该图允许胶囊脚面与台阶边缘接触，属于源几何检查，不能单独证明目标物理。

F 的 [审查 Schema](../../schemas/style042-review-0.1.0.schema.json) 只允许接受或列出已存在场地的问题；本入口遇到 revise 明确停止，没有实现完整上游返修调度。文字 concept/evidence 不视为构件存在的依据，最终通过状态需核对本地报告和目标证据。

目标项目单独导入 GLB，以实际源文件哈希、每个网格 bounds 和非水体 MeshCollider 核对，再另进程重开。截图使用同一组相机；展示材质使用统一 Standard 着色器及 GLB 原有颜色/透明度。Play Mode 的 CharacterController 按连续路线实际移动，记录道路到每间房及上层的通过/失败。自由查看相机与实走验证器是独立组件。

色块材质、阶梯屋顶、简单树形、64m 固定小街区仍是限制。它不是四个全场景的统一验收，也不包含 Minecraft 实贴、城市规模、城堡、动画或联网资产检索。

## 录制与回放

同一有界监督器保存响应、usage、Schema、错误、skill/hash 和接受记录。v1、v2 失败保留。v3 在修正源路线采样后按完全相同的请求哈希复用 v2 的六次实际响应，补调用 F；它是续跑，不是独立成功率样本。新网络请求与复用记录分开计数，程序计账包含复用 usage，并非 v3 新增账单。

最终零网络回放要求代码/配置/登记和请求一致，比较世界包、GLB 和源细几何字节。实际 Unity 结果单独存于 `unity-evidence/`，源运行 `result.json` 中的目标 `not_run` 是导出时状态，不能直接覆盖后续独立目标验证报告。
