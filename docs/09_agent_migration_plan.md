各主工单拥有完整接受门槛和自己的真实批次，不再另设贯穿所有阶段且无法收口的“总验收工单”。需要付费调用或目标环境时按实际可用条件留证，缺环境不写通过。成功率阈值、样本、预算与失败计入规则在每批执行前固定。

## 4. 复用与迁移策略

| 现有部分 | 处理方式 | 兼容/回退要求 |
|---|---|---|
| Provider.complete | 新增统一行动/工具结果适配，保留旧路径 | 新版明确选择协议版本，不把旧 json_contract 当作行动协议 |
| 固定 Supervisor | 版本路由到新运行时，复用预算/事件机制 | 0.1.0 fixture 和精确回放保留，失败不自动切换旧规则规划 |
| E 显式盒体设计 | 逐步增加显式注册的参数构建、检查与预览工具 | 不隐式启用旧模板；几何能力逐项声明和验收 |
| Compiler / WIR / Repository | 复用，补稳定身份、候选和读写依赖 | 旧世界/响应保持原版本；升级创建新记录，保留原件 |
| Unity/Minecraft 序列化 | 复用格式与坐标经验，补目标 profile 和场景对象 | 旧路线目标证据不迁作新 Agent 验收 |
| 网页与桌面宿主 | 渐进接入动态任务、候选、连接和修改 | 041 Figma 仅为设计参考；当前 025/026 能力保持准确标注 |

迁移发布使用显式协议/能力版本；旧版可继续用于旧任务/回放。新任务失败保留原修订并报告原因，不能偷偷降级生成。新存储格式上线前测试旧包读取、升级副本、失败恢复与导出一致性。数据库、几何精度、协议版本的具体选择由对应契约工单核对后冻结。
