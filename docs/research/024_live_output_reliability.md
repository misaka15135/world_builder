# 024 真实模型输出可靠性：证据与 029/030 改造建议

日期：2026-10-12。状态：设计建议，非已实现能力。适用范围：当前固定 A—F 的 0.1.0 原型及后续 029/030 契约升级；不把历史失败改记为成功。

## 已观察到的问题

- 023 的人工固定响应通过校验、WIR 编译和双目标导出，证明的是「接受有效计划后的本地链路」；不是模型对任意描述的生成质量证明。
- 024 v2 的 A 响应是有效 JSON，却把道路、入口和房间拆成独立场地需求，触发场地预算；v4 把道路继续归为 C 类型和 D 场地，最后因场地尺寸失败。这是需求角色和跨阶段引用的语义问题，不是 JSON 语法问题。
- 024 v3 的 E 两次为 `api.incomplete`，旧日志未保存 `finish_reason` 或该失败响应的服务端 usage，不能断言就是输出上限截断。新增诊断只面向未来运行，不能倒填旧记录。

## 外部一手资料及适用边界

1. [DeepSeek 官方 JSON Output](https://api-docs.deepseek.com/guides/json_mode/)（访问 2026-10-12）要求 `json_object`、明确的 JSON 指令和合理的输出上限；文档说明仍可能出现空内容。它承诺的是 JSON 字符串，不是项目 Schema 或场景语义。当前官方 Chat Completions [接口说明](https://api-docs.deepseek.com/api/create-chat-completion/)列出 `finish_reason=length` 等结束原因和 usage 字段。本项目不得推断 `json_schema` 严格模式在当前 DeepSeek endpoint 上可用。
2. [OpenAI 官方 Structured Outputs 说明](https://developers.openai.com/api/docs/guides/structured-outputs)（访问 2026-10-12）区分 JSON 模式与 Schema 约束，并要求处理拒答及输出上限等不完整情况。这里只借鉴通用边界；OpenAI 的 `json_schema` 保证不能直接套用到 DeepSeek。
3. [Reddy 等，ICML 2026](https://proceedings.mlr.press/v306/reddy26a.html)报告受约束解码会提高结构有效性，但可能把生成推向结构正确、语义错误的路径；其草稿再约束方法是研究结果，不是本项目已验证的改进方案。项目是否采用双遍生成，须单独评估调用费用与真实案例质量。

## 建议的职责划分

| 层 | 应负责 | 不应宣称 |
|---|---|---|
| 服务端 JSON 模式 | 尽量返回可解析 JSON | 自动满足本地 Schema、道路/场地语义 |
| 本地 Schema | 字段、类型、枚举、范围与引用形状 | 理解开放语言的真实意图 |
| 跨阶段验证器 | 检查需求类型、产物类别、ID 覆盖、尺寸与空间约束 | 静默删改模型/用户要求 |
| 有界返修调度 | 按错误归属退回最早错误阶段，失效依赖，重新验证 | 无限重试或越过预算 |
| 离线/真实评估 | 固定响应做程序回归；真实响应单独记录格式、语义、产物质量 | 用 fixture 成功代替真实 API 成功 |

## 029 契约建议（需先冻结新版，不原地改变 0.1.0）

1. A 的需求使用明确类别与单位，至少区分可建造场地、道路/通行网络、地形条件、建筑内空间，以及自然对象/实例组。数量预算按类别计算；道路和房间不占建筑场地数。每条需求保留稳定 ID、必需性、空间关系与验收条件。
2. C 的目录项声明对象类别和来源需求 ID；D 的场地只能引用可建造场地类，`roads` 只能满足道路网络类；E 的室内空间需要引用所属建筑及室内需求。F 的覆盖检查同时检查对象类别和证据，不能靠一条自述 `satisfied=true` 通过。
3. 定义错误归属。例如 D 发现「道路被当作场地」时，允许有界退回 A/C 并使下游计划失效，而不是在 D 重试同一错误依赖两次。返修过程仍须保留全部原始响应和计费；不能自动把道路对象重写为别的类型并声称模型设计完成。
4. 保留旧 Schema、fixture 和回放；新版请求与响应必须带新契约版本。不兼容时显式拒绝混用。

## 024/030 执行与验收建议

- 先用 v2/v4 的匿名化失败形态建立离线负例，再为新版冻结建筑街景、纯自然和混合场景正例；既有 v1—v4 真实运行记录不改分母。
- 对 E 不完整响应，先记录 `finish_reason` 与服务端 usage；只有确认是 `length`，才针对该任务缩小输出、拆分设计内容或调整输出上限。若是拒答、资源中断或空内容，分别处理，不一律增加 token。
- 新契约和调度通过离线测试之后，再预登记一版有限预算的真实 DeepSeek 批次；逐阶段区分 JSON 错误、Schema 错误、语义/几何错误、返修与最终 WIR/目标导出。目标侧实际加载和通行仍单独验收。

本调研写作时仅实现了未来不完整响应的安全结构化留证。随后 029 开始[独立的需求分型草案](../contracts/scene-requirements-v0.2-draft.md)，但尚未接入 API 运行时；上游返修和 E 拆分仍未实现。
