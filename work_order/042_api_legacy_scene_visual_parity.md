## 目标与范围

近期目标是让真实 DeepSeek API 生成魔法城邦、现代都市、工业园和港口，在 Unity 中具有接近已有本地规则版的场景丰富度、代表性形体和细节。Unity 是首要查看与观感验收目标；Minecraft 导出单列检查，旧游戏截图作历史参照，不能当成本次 Unity/API 证据。

本阶段采用显式的模型规划与本地几何构建：模型提出需求、类型/数量、布局、建筑族和受限参数，本地监督器验证后调用已有详细构建能力并写入 WIR。不得把完整旧世界复制后标为真实模型生成，也不得在 API 失败后静默调用旧 `compile_brief/plan_siting/design_sites` 替代模型决策。可复用它们内部已核实的构件实现和确定性设计规则，但每项设计选择的模型/本地来源必须记录。

四场景迁移不等待完整通用资产库、联网查找 skill、自然场景任务系统或用户编辑器；这些扩展保存在 043 及既有工单。042 只实现这四个场景必需的契约与目标能力子集，并与 029/035 共享定义，避免创建另一套长期通用框架。041 的单房壳体保持旧实验口径。

## 验收标准

四个场景各自具有真实模型计划、完整可校验源世界、Unity 实际加载/重开证据和可供用户比较的同设置截图；必须对象及明确要求的建筑细节不能被无声省略，关键通路有适用目标证据。基线允许旧有的方块化风格和已登记缺陷，不额外承诺照片级效果。未达到任何场景项则如实保留未完成状态。
