## 目标与范围

按简报给出**地形方案**：地貌单元、水系与可建设适宜度，作为 016 选址的输入。这是用户规划里的 B，对应正式方案 §4.2 的"区域骨架"与"生态与用地"。

现状对照：今天的地形是解析函数 `planner.height()`（一个正弦项加按 x 的线性渐变）加**城市正中 8 m 宽的直条河**，没有河网、丘陵、海岸、坡度统计，也没有"保留区"。详见 [docs/04_scene_pipeline.md](../docs/04_scene_pipeline.md) §2。

## 输入输出契约

`TerrainPlan` 至少包含：

| 字段 | 含义 |
|---|---|
| `relief` | 地貌单元与控制点（山脊/谷线/台地/平地），含高程范围 |
| `hydrography` | 水系中心线与宽度、等级（主河/支流/海岸线）、流向与出图边界 |
| `buildable` | 可建设适宜度场与保留区（坡度上限、积水区、景观保护区） |
| `sampling` | 采样间距与实测的坡度/高差统计（用于核对简报要求） |

对应 WIR：`terrain`（高程场资源）、`river`（河道几何）、以及新的保留区实体（`kind` 为自由字符串，无需改冻结 Schema）。

## 工作项

- [ ] 定义 `TerrainPlan` Schema 与单位；高程、坡度、宽度全部显式。
- [ ] 实现规则版地形器：控制点插值生成低频地形 → 按排水方向生成河网（不再固定直线）→ 局部修整（建筑平台/河岸）→ 输出适宜度场。
- [ ] 为四个背景包各写 `terrain.json` 偏好（魔法城邦：河谷 + 丘地 + 一条主河与支流；现代都市：大平原 + 人工水道；工业园：平缓地 + 运河/铁路廊道；港口：海岸线 + 港湾）。
- [ ] 独立校验规则：水系连通、出图边界明确、坡度/高差在背景偏好范围内、保留区不与建筑适宜区冲突、河道与地势不矛盾（不出现"河往高处流"）。
- [ ] 让 016 能在**不改动地形**的前提下完成整城选址；若某背景在地形上不可行，返回 `infeasible` 并指出冲突，而不是偷偷推平地形。
- [ ] 记录实测：同一简报在四个背景下的坡度/高差/水域占比统计。

## 验收标准

- 同一简报与种子两次生成的地形方案逐字段一致，且能回放。
- 四个背景包产出的地形在统计上明显不同（例如港口的水域占比与海岸线长度显著高于工业园），并有数字证据。
- 河道不再固定为直线：至少一个背景产出带弯曲与支流的水系，且 016 的道路/桥梁能正确跨越。
- 硬约束失败有作用域与冲突说明；不出现"候选没找到就宣称无解"。

## 明确不做

- 不做真实水文/水力学仿真，不承诺工程地质结论。
- 不做选址与路网（016）、不做建筑（017）。
- 不改动已冻结的 128 m 试验地形（`height()` 路径保留，仅供旧修订与历史证据使用）。
