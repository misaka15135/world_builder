## 目标与范围

按简报给出**地形方案**：地貌单元、水系与可建设适宜度，作为 016 选址的输入。这是用户规划里的 B，对应正式方案 §4.2 的"区域骨架"与"生态与用地"。

现状对照：今天的地形是解析函数 `planner.height()`（一个正弦项加按 x 的线性渐变）加**城市正中 8 m 宽的直条河**，没有河网、丘陵、海岸、坡度统计，也没有"保留区"。详见 [docs/04_scene_pipeline.md](../docs/04_scene_pipeline.md) §2。

## 输入输出契约

`TerrainPlan` 至少包含：

| 字段 | 含义 |
|---|---|
| `relief` | 地貌单元与控制点（山脊/谷线/台地/平地），含高程范围 |
| `hydrography` | 水系中心线与宽度、等级（主河/支流/海岸线）、流向与出图边界 |
| `buildable` | 可建设适宜度场与保留区（坡度上限、积水区、景观保护区） |
| `sampling` | 采样间距与实测的坡度/高差统计（用于核对简报要求） |

对应 WIR：`terrain`（高程场资源）、`river`（河道几何）、以及新的保留区实体（`kind` 为自由字符串，无需改冻结 Schema）。

实现说明（与工单原文的差异，如实记录）：

1. 地形不是"控制点插值 + 排水求解"，而是 **区域斜坡 + 平行于排水方向的皱褶 + 有界顺坡波纹**，并在水道附近把皱褶衰减到零。原因是硬要求"水道必须出图且单调下降"：先做控制点插值再找排水，会让河道要么停在洼地、要么被强行切穿山体（实测出现 60° 以上的假峭壁）。当前模型的下降是构造保证的，校验器仍然独立复测。真正的排水求解器属于后续升级。
2. `water.coast` 布尔字段已删除：海岸线就是 `kind: "coast"` 的含义，同一事实写两遍只会互相矛盾。
3. 与 006 高程资源的对接（把 `TerrainPlan` 写进 WIR 的 `terrain`/`river` 实体）**不在本工单完成**，归 018 装配阶段。
