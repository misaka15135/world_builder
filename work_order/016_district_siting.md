# 016 区块归属与选址（流水线 D）

- 状态：planned
- 创建日期：2026-09-26
- 执行者：待认领
- 依赖：014（地形方案）、015（风物目录）
- 修改范围：未来的 `world_builder/planning/blocks.py`、`settings/<name>/districts.json`、`tests/test_siting.py`、`docs/contracts/siting-v0.1.md`

## 目标与范围

在地形上做**宏观划分 + 骨架 + 选址**：大小不一的区块、若干区块同属一个城邦/城堡的归属层、道路/轨道/水系骨架，并为每栋建筑给出**最大占地与最大高度的包络**与场址要求（朝街/贴水/靠铁路/居中）。这是用户规划里的 D，也是用户此前裁定纳入 006 的"宏观街区归属"与"非正交路网"的正确落点。

现状对照：今天是 3 条南北向等宽带（固定 `x_pitch=42/44`、`y_pitch=52/56`）、固定 32×28 m 地块、固定竖向净空、固定 4 m/3/4/6 m 宽的正交道路；没有归属层、没有大小不一的区块、没有非正交街网。详见 [docs/04_scene_pipeline.md](../docs/04_scene_pipeline.md) §2。

## 输入输出契约

| 产物 | 关键字段 |
|---|---|
| `domains[]` | 归属/领地：`id`、`kind`（城邦/城堡/庄园/港口区）、包含的 `block_ids[]`、规划参数覆盖（密度、层数上限、路宽、规则度） |
| `blocks[]` | 区块：`id`、`domain_id`、`polygon`、`use`（居住/市场/政务/工业/港区/绿地）、面积 |
| `network` | 道路/铁路/桥/码头骨架：中心线、宽度、等级、跨越关系 |
| `sites[]` | 选址：`id`、`building_type`（来自 015）、`block_id`、`envelope{max_footprint_m2, max_height_m, max_storeys}`、`access`（接哪条路/岸线）、`orientation` |

包络必须包含 015 中该类型的 `footprint_m2_range`/`height_m_range`，且不与其他 site 重叠、不压 014 的保留区与水域。

## 工作项

- [ ] 定义 `domains`/`blocks`/`network`/`sites` Schema；显式单位与面积/高度上限。
- [ ] 实现规则版划分器：按地形与目录需求切区块（大小不一），支持"若干区块归属同一 domain"并让 domain 覆盖规划参数。
- [ ] 实现骨架：道路按中心线与宽度铺开、桥/涵跨水、可含铁路与码头；至少一个背景产出**非正交**街网（按地形与语境弯曲，而非横平竖直）。
- [ ] 实现选址：按目录的 `needs`/`adjacency` 在 block 内分配 site 与包络；中心区路更宽、建筑更高，边缘区路更窄、更密、更曲折。
- [ ] 独立校验规则：区块面积与目录一致、骨架连通、每栋有包络、包络不重叠、包络不压水系与保留区、必现风物全部有 site。
- [ ] 用一个 512 m 样例做端到端演练：地形 → 区块 → 骨架 → 选址，并记录"哪些 site 的包络撑不下 015 的要求"这类冲突。

## 验收标准

- 同一输入两次得到一致结果；冲突有具体作用域与原因，失败回馈到 014（地形不可行）而不是整城重跑。
- 至少一个样例中，**多个区块同属一个 domain** 且该 domain 的参数确实生效（例如城堡领地内建筑更大更密、路更宽），有数字证据。
- 至少一个样例中街网不是正交网格（道路方向角分布与正交基线的偏差有统计）。
- 每栋必现风物都有包络，且包络面积/高度落在 015 声明的区间内。

## 明确不做

- 不做单栋外形与房间（017）、不做装配（018）。
- 不承诺道路符合真实交通工程；这是可校验的生成器输入。
