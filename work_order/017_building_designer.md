## 目标与范围

给一栋建筑一块包络与一个类型，产出**这栋自己的设计**：外形轮廓、层数与层高、每层房间划分、楼梯与竖向通道、入口与门洞、屋顶原型、材质、家具布置。这是用户规划里的 E，也是"每栋不再一样"的关键。

现状对照：今天每栋的形态是"按种子取宽度/进深/层数 + 按功能查表"，平面只有一种模板——"楼梯井以东切两间房 + 一道隔墙"，家具按用途查表；没有单栋设计产物，没有按背景/包络变化的平面。详见 [docs/04_scene_pipeline.md](../docs/04_scene_pipeline.md) §2。

## 输入输出契约

`BuildingDesign` 至少包含：

| 字段 | 含义 |
|---|---|
| `outline` | 各层轮廓（可退台，米；与 006 的 `storey_insets_local_m` 对齐） |
| `storeys[]` | 层号、层高、楼板厚度、楼板开口（楼梯井） |
| `rooms[]` | 房间：所属层、用途、边界、面积 |
| `stair` / `vertical` | 楼梯类型（直跑/转折）、梯段、净空、落地点 |
| `entry` | 入口侧、偏移、宽度、高度、门洞与门楣 |
| `roof` | 原型（双坡/尖塔/平顶/退台）、高度、出檐 |
| `materials` | 墙体/楼板/屋顶/腰线的材质词汇（由背景包映射到具体方块或材质） |
| `furniture[]` | 家具：用途、位置、尺寸、所属房间 |

## 工作项

- [ ] 定义 `BuildingDesign` Schema；所有尺寸显式单位，且必须在 site 包络内。
- [ ] 把 006 已验证的形状规则搬进来作为**参考实现**：多层壳、楼板开口、隔墙与门洞、直跑楼梯、逐层退台、屋顶原型、出檐、楼层腰线。
- [ ] 设计条目（`designs/*.json`）先行：住宅、商铺、工坊、图书馆、旅店、教堂、市政厅、公寓、写字楼；再补港口/工业园所需（仓库、码头、船坞、厂房、货场、灯塔、车站）。
- [ ] 让平面随包络与背景变化：同一类型在不同占地/高度下产出不同层数与房间划分，而不是同一模板缩放。
- [ ] 建筑规划 skill：把"如何为某类型排外形/层/房间/楼梯/家具"写成可复用的技能文件，供后续新增类型时按同一流程扩展。
- [ ] 独立校验规则：外形在包络内、房间不重叠且在层内、楼梯落地并与楼板开口对齐、入口接路、家具不挡门不占通道、屋顶与风格一致。
- [ ] 成本策略：默认"设计模板 × 站点参数"实例化；只有地标类型允许单独设计入口（模型可选），并记录调用次数。

## 验收标准

- 单栋设计与现有目标适配器兼容：同一份设计在 Minecraft 与 Unity 适配器下都能导出，且不出现 006 曾经踩过的缺陷（屋顶只写属性、门洞量化成一格、浮点 epsilon 中断导出）。
- 同一类型在三种不同包络下产出**可核对的差异**（层数、房间数、面积分布）。
- ≥ 6 种功能原型（含至少一个地标类型）各有独立规则通过；家具全部落在房间里且不挡通道。
- 设计批次可离线运行，零模型调用；模型路径与离线路径产出同一 Schema。
- 复用地标样例做一次目标平台实贴或导入，避免"离线好看、进游戏不对"。

## 明确不做

- 不写方块/三角面几何；设计只产出可校验的参数化描述，几何仍由适配器派生。
- 不做选址（016）与装配（018）；不训练模型。
