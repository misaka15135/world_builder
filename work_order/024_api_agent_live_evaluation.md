- 创建日期：2026-09-29

- 依赖：023；新增能力批次分别需要 031、034、036

## 目标与范围

对 023 的真实 API 调用完成率、返工率、成本、设计质量和目标可用性进行可核对的验收。接入用户实际选择的服务；比较供应商时保持用户需求、契约、预算和 skill 版本一致，不承诺更换模型后结果相同。

## 当前分批验收路线（2026-10-10）

首批仍可直接针对既有 023 和 008/009 可用目标环境开展，不等待所有新增工单。随后在 031/036 完成后追加无建筑森林溪流、森林营地等自然/混合批次，在 033/034 完成后追加用户修改批次。各批次单独冻结输入、版本、预算、样本与适用目标检查，旧批次不重写分母。质量证据随实际功能和用户反馈积累，不另起脱离实现的质量专项。

本工单最终收口需要既有能力、自然/混合场景和用户修改三类批次均有实际记录，及 036 首批目标的真实模型场景证据。037 新平台、007 完整手工编辑和 010 独立世界不属于收口前置条件。

## 工作项

- [ ] 使用用户配置的 HTTPS endpoint、模型和环境变量密钥完成小场景真实调用，保存各阶段响应与 usage。
- [ ] 预登记至少单层建筑、两层商铺、多个场地与起伏地形四类场景，明确样本量、预算、成功标准及失败计入方式。
- [ ] 记录初次完成、格式失败、几何失败、返工、最终失败、耗时及实际 token；人工评审需求符合程度、空间布局、风格和目标可用性，记录实际人工修整步骤。
- [ ] 对真实响应进行离线回放、世界包往返和目标文件一致性检查。
- [ ] 将同一修订导入 Minecraft 与 Unity，验证坐标、材质、实体数及适用碰撞/支撑；含入口、多层建筑或桥时验证对应连续通行，不要求自然场景补出这些对象。
- [ ] 在自然与混合能力交付后冻结追加批次，验证零建筑/零道路任务、对象清单、分布条件和双目标实际表现；失败仍进入分母。
- [ ] 在修改入口交付后冻结材质调整、对象移动、河道修改和重新导出批次，核对实际重执行范围、保护对象、修订、撤销/重做和用户反馈。
- [ ] 明确船只、干船坞、曲面、挖方及细尺度楼梯的后续契约扩展需求，保持本次能力边界可见。

## 验收标准

真实服务结果必须能关联到请求、响应、skill/契约版本和导出修订；失败不能从分母中删除。目标侧证据需区分文件结构、实际加载、碰撞和连续实走。只有实际执行的检查能标记通过；fixture 与模拟 HTTP 测试不能计为真实模型样本。具体批次标准在首次运行前冻结。
