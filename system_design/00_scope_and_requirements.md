# 00 目标、需求与证据边界

日期：2026-11-11。版本：design-2026-11-11。性质：系统详细设计草案；不是当前运行契约或功能验收。

## 1. 产品定义

系统面向玩家与场景创作者：用户连接受支持的 LLM，描述场景，由 Agent 使用版本化知识与工具完成需求拆解、空间设计、候选构建、诊断修正、预览、源世界修订及多目标导出。自然、建筑、混合场景具有同等地位；无建筑、无道路的森林是合法需求。

闭环为“描述 → 需求与任务 → 行动/工具/观察 → 候选 → 本地接受 → 反馈修改 → 导出”。输出是可追溯的游戏场景，不承诺玩法生成、任务系统、自动线上投稿或工程安全认证。IFC、任意曲面、大世界流式编辑、新游戏平台、完整手工编辑器为条件扩展，不构成首批隐含依赖。

## 4. 关键用户场景

### UC01 单栋创建（M1）

前置：连接能力通过，场地固定，工具/profile 可用，预算已配置。用户提交建筑描述；运行时接受需求和任务；Agent 查询场地、构建、检查，根据诊断改参数；候选预览后按已授权接受策略提交。后置：得到不可变修订和运行记录；失败保持原头。固定场地结果不等于完整场景规划能力。

### UC02 无建筑森林（M2）

需求包含地形、溪流和树石数量/分布；能力图只安排相关地形、水、资产、布局、分布与审查任务。建筑任务不产生，C/D 的对象和空间职责仍存在。若水体只有静态表达，必须显式告知不含动态流体。自然对象的避让、支撑与资源密度仍需校验。

### UC03 森林营地（M2）

地形与资产初稿可并行；D 布局检查坡度、水线、树木与建筑入口空间；E 构建营地设施与实例组。跨对象规则在装配候选后检查。Unity 与 Minecraft 使用同一修订，分别映射几何与材料。

### UC04 修改屋顶并锁定树林（M3）

请求绑定选中对象、基础修订及锁版本；读集包含屋顶、支撑、包络与邻域查询。更新屋顶的稳定对象身份，失效相关检查和导出；锁定树木不变。若屋顶扩大侵入树冠，返回冲突或请求方案选择，不自动删除树木。

### UC05 崩溃后继续

重启从持久化 Operation、Task、ToolCall 回执恢复；查询工具与模型调用的不确定状态。已接受修订可直接打开；不根据聊天摘要推断成功。若供应商请求是否计费未知，记录未知用量并按保守预算处理。

## 5. 非功能目标的写法

性能、容量和成功率数值必须与机器配置、场景规模、profile、模型、协议及试验日期绑定。当前未运行性能或真实模型批次。本设计给出预算维度与测试方法，具体阈值见 12 章的建议值与冻结要求，不能作为 SLA。

优先级顺序：数据完整性和权限边界 → 可诊断失败与恢复 → 双协议行为一致性 → 目标平台可用性 → 性能和视觉质量优化。控制层不为提高成功率修改用户必要需求。

## 6. 术语

`accepted task` 表示任务产物可供依赖任务消费；`accepted revision` 才表示正式世界提交。`candidate` 是隔离候选；`artifact` 是带内容摘要的资源；`profile` 是锁定版本的目标能力声明；`operation` 是一次用户意图及其总预算；`scope` 包含对象、空间与能力限制。模型总结不作为精确世界数据库。
