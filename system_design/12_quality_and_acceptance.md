# 12 质量属性、测试策略与验收证据

日期：2026-11-11。性质：目标质量计划，版本 `design-2026-11-11`。本文件定义未来实施与验收方法；没有执行真实模型批次、数据库恢复实验或目标平台加载。053 的文档校验不能代替 048—052 产品验收。

## 1. 质量目标及可证伪判据

| 属性 | 刺激与场景 | 必须可观察的结果 |
|---|---|---|
| 完整性 | 任意步骤失败、取消或磁盘满 | 正式头未错误推进，已接受资源可读取 |
| 权限安全 | 模型要求越界写、解锁、绕过规则 | 网关/接受事务明确拒绝，留下定位诊断 |
| 协议一致性 | 同一规范化行动从两条协议进入 | 相同权限、预算、作用域与提交判定 |
| 可恢复性 | 工具运行中进程退出或连接断开 | 持久回执恢复；未知副作用不盲重试 |
| 可修改性 | 只改屋顶，树林被锁 | 无关 ID/内容不变，必要邻域重新校验 |
| 可移植性 | 同修订导出 Unity 和 Minecraft | 保留来源映射，逐对象损失和目标证据分离 |
| 可解释性 | 必需能力缺失、预算耗尽或等待选择 | 用户看到原因、影响与下一动作，无伪成功 |
| 可复现性 | 固定源、工具、种子及版本离线回放 | 可比对的规范化输出/摘要；不暗中联网 |

必需需求、用户锁和本地硬规则优先于视觉评分；不能为了提高成功率而排除失败样本或缩减要求。

## 2. 测试层次与隔离

| 层次 | 测试对象 | 输入/隔离 | 产物 |
|---|---|---|---|
| L1 契约与纯函数 | Schema、单位变换、图环、参数检查、哈希 | 固定 fixture；不调用模型 | 正反例及边界断言 |
| L2 领域与属性 | 几何、引用完整性、ID 稳定、锁、路径 | 生成边界数据与固定种子 | 可复现失败最小样本 |
| L3 组件集成 | Runtime/Gateway/Repository、两个适配器 | 可控假 Provider/工具、临时仓库 | 事件、回执、事务状态 |
| L4 故障与安全 | 崩溃、取消竞争、重复键、包攻击、注入 | 注入点、资源限额、隔离目录 | 恢复前后状态及失败分类 |
| L5 真实模型行为 | 两协议工具选择、观察与修正 | 预登记模型/预算/输入 | 原始可见响应、规范化动作、真实工具结果 |
| L6 目标与交互 | 引擎加载、保存重开、连续通行、UI | 固定目标版本、角色参数、相机 | 日志、录屏、截图及版本清单 |

L1—L4 可证明机制正确性，不能外推模型质量；L5 不能证明目标平台可用；L6 的视觉好看不能替代源世界不变量。对纯文档本轮执行链接、图表、契约样例与一致性验证即可，不新建与实现无关的产品测试。

## 4. 关键不变量测试

- I01：任何非法候选、任务失败、取消、预算耗尽不得产生错误正式修订。
- I02：`head_generation` 每次正式头更新严格递增；恢复相同内容也不得复用旧 generation，防止 ABA。
- I03：相同接受幂等键和请求摘要返回同一修订；同键不同输入拒绝。
- I04：候选验证绑定 patch、base、锁版本、规则和 profile 摘要；任何变化使原验证失效。
- I05：空间查询“没有对象”也产生可追踪区域依赖；另一个候选插入邻域物体必须触发冲突或复验。
- I06：accepted Task 只是依赖产物可用；只有最终候选接受事务推进世界头。
- I07：不可变 Revision、Artifact 不原地覆盖；所有引用可解且内容摘要一致。
- I08：撤销/重做复用已有快照，创建以当前头为父的新审计修订并记录 `restored_from`；不调用模型，仍检查当前锁。
- I09：导出配置变化只重建派生产物，源 WIR 和模型调用量保持不变。
- I10：缺 usage 仍有限终止；“未知”费用不能当作零消费重新获得预算。

属性测试可随机生成操作序列、冲突区域和中断点；失败用例固定种子并缩减为最小复现。测试 Oracle 应来自不变量和独立规则，不仅复写被测实现步骤。

## 5. 故障注入矩阵

| 注入点 | 检查项 | 接受结果 |
|---|---|---|
| 预算预留后、模型请求前 | 预留回收与状态持久化 | 无重复派发、无无限冻结预算 |
| 模型发出后、响应保存前 | unknown 调用和费用 | 保守预算，显式恢复策略 |
| 工具副作用完成、回执丢失 | 幂等键/结果查询 | 不重复副作用，不虚构失败未执行 |
| worker 写 blob 中途 | 半文件与清理标记 | 无有效 artifact 引用半文件 |
| blob 完成、数据库提交前 | 孤儿资源和 GC | 可安全回收，正式头不变 |
| DB 提交后、UI 通知前 | 回执/事件重放 | 返回同一修订，不二次提交 |
| 取消与接受同时到达 | 持久取消代数、事务顺序 | 只出现一种有序结局；UI 解释实际先后 |
| 用户锁更新与接受竞争 | 锁版本和重检 | 不能提交违反新锁的候选 |
| 备份写入 SMB 时断网 | 完整性标记与本地快照 | 不把部分网络副本标可恢复 |
| 资源达到上限 | 内存、输出、磁盘余量 | 有界失败，保留已接受源数据 |

并发测试需要屏障精确控制时序，不能仅“多跑几次没遇到”作为竞争正确性证据。

## 6. 双协议与里程碑验收矩阵

| 阶段 | `native_tools` | `action_json` | 共用接受门槛 |
|---|---|---|---|
| 049 机制 | 原生 call ID、工具观察回传、截断/重复负例 | 严格 JSON、关联 ID、未知动作/字段、修正上限 | 同一 Gateway/预算/候选权限；实际只读 MCP 调用/断连恢复 |
| 050 / M1 | 真实单栋工具失败→有效修改→候选提交 | 独立完成相同行为 | 固定场地；保存、重开、无网络回放、GLB/schematic 文件 |
| 051 / M2 | 预登记三类场景覆盖批次 | 预登记三类场景覆盖批次 | 知识/资产、必需对象、同修订双目标加载/重开/适用通行 |
| 052 / M3 | 真实局部修改批次与调用审计 | 独立修改批次与调用审计 | 屋顶/材质、移动对象、河道、仅换导出；锁、稳定 ID、撤销 |

两种模式可使用同一支持相应能力的服务，但必须分别保留请求和结果。M1 不强行承担 M2 三类完整场景；M2 的目标加载不反向证明 M1 已具备自动导入功能。未知环境和未执行项目保留 `not_run`。

## 7. 真实模型实验预登记

每批执行前冻结：场景文本与必需约束、协议、模型/endpoint 版本标识、输入上下文、工具/Skill/知识/profile 版本、样本数与种子、温度等可用采样参数、预算、成功判据、停止规则和人工干预规则。供应商不提供精确版本时记录返回的模型标识与日期，不虚构可完全复现模型权重。

案例至少包含正常构建、一次真实可修复诊断、能力缺口、预算不足和取消/失败机制；机制负例可由可控环境注入，但必须标注，不能伪装成自然模型失误。Agent 修正须对比工具输入与输出，证明修改针对实际诊断且产生有效变化。

统计分母包含所有已启动尝试，分类记录认证/服务故障、协议失败、领域失败、预算退出、人工修整和成功；明确哪些属于产品成功率、哪些属于供应商可用性。不得删除失败重跑后只保留最好结果。样本量与成功阈值由各阶段预登记，本设计不宣称未经测量的成功率。

## 8. 证据分层与记录格式

| 证据维度 | 最低内容 | 不能推断的结论 |
|---|---|---|
| 人工/模拟响应 | fixture、模拟工具标识、运行日志 | 真实模型会选对工具 |
| 真实模型调用 | 请求/响应引用、模型、协议、usage 来源、工具链 | 目标平台可加载 |
| 源世界校验 | revision/hash、规则版本、定位诊断 | 引擎碰撞和角色通行 |
| 文件结构 | 文件摘要、格式解析、对象/资源映射 | 游戏中实际观感和可用性 |
| 目标加载/重开 | 引擎/插件版本、导入设置、加载日志、保存重开证据 | 所有路径连续可走 |
| 实走 | 角色尺寸、控制器、路径、入口/楼梯/桥、录屏 | 视觉风格满足用户偏好 |
| 视觉评审 | 固定视角、评分量表、评审者、局限 | 工程安全认证或无几何错误 |

建议证据记录包含 `evidence_id, dimension, status, source_revision_id, artifact_hash, environment, procedure_ref, result_ref, reviewer, recorded_at`。`status` 为 `passed/failed/not_run/not_applicable`；`not_applicable` 必须附适用性理由，不能用于跳过失败检查。证据维度独立存储，不用单个总通过字段覆盖全部层次。

## 9. 性能、资源与视觉评估

性能数值以下均为实验建议，待实现测量后冻结，不是现有指标或 SLA：

| 场景 | 建议观测目标 | 测试边界 |
|---|---|---|
| 本地状态查询/取消请求受理 | p95 ≤ 500 ms | 本机单会话、固定对象摘要量；不含远程取消完成 |
| UI 收到新事件 | 正常运行下 ≤ 1 s | 轮询/推送周期与背压配置固定 |
| worker 并发 | 从 1—2 开始对照 | 报告吞吐、RSS、控制响应；不默认越多越快 |
| 校验/导出 | 记录 p50/p95 和规模增长曲线 | 对象数、实例数、体素/三角形数、输出体积明确 |
| 历史恢复 | 记录本地耗时、零新增模型调用 | 大资源复用与索引重建分开 |

内存/磁盘/实例配额取决于硬件和目标 profile，先测再定；超限测试是必需。视觉评分建议分需求符合、空间可读性、风格一致、对象多样性和明显瑕疵五项；评审者盲化协议来源以减少偏见，报告样例与分歧，不用单一平均分掩盖必需项失败。

## 10. 发布门禁与本次设计验收

产品发布至少需要：相关工单契约/回归通过；安全与数据完整性无未处理阻断项；旧版回放和包读取可用；版本锁与限制说明齐全；对应阶段的真实双协议与目标证据完整。未具备目标环境时可交付阶段性文件，但不能标该目标已验收。

053 文档交付检查仅包括：需求 R01—R14 有设计/测试/工单承接，所有相对链接可解，UML/流程图源码可渲染，图文实体/状态一致，示例通过草案校验，`python3 tools/check_project_docs.py` 通过。执行结果写入设计包验证记录和 [053 工单](../work_order/053_system_architecture_design.md)。
