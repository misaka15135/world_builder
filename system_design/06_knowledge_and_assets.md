# 06 知识、Skill、配方与资产设计

日期：2026-11-11。设计标识：`design-2026-11-11`。目标设计草案，非已实现的检索或自然资产系统；公共数据契约由 048 冻结，运行接入由 049/051 实施。

## 1. 职责与数据分层

知识层服务于设计依据与可用资源选择，不持有世界写权限。精确尺寸、对象位置、锁和修订从 Repository 查询；知识检索只回答适用原则、案例、工具用法和资源候选。基础内容随本地应用提供，不要求额外云账号；可选远程来源独立配置。

| 类型 | 作用 | 不可代替 |
|---|---|---|
| Skill | 版本化任务方法、检查清单、输出约定 | 工具授权、硬约束或用户需求 |
| KnowledgeDocument / Chunk | 带来源的设计参考和平台资料 | 当前世界事实、平台加载证据 |
| Recipe | 版本化参数定义与确定性构建算法引用 | 模型未作出的布局、数量或风格选择 |
| AssetDefinition | 可复用几何、材质及能力元数据 | 世界中的实例身份 |
| AssetInstance | 稳定 ID、变换、资产版本与实例覆盖项 | 全局资产定义的隐式修改 |
| Provenance | 来源、版本、处理链、引用与许可记录 | 自动确认第三方权利或内容正确性 |

A—F 按任务请求相应知识；C 搜索资产并解释选择，D 使用实际包络布局，E 使用配方与工具构建。F 检查来源、覆盖与效果，但其判断不能把缺失文件变为可用资产。

## 2. 最小记录与存储

| 记录 | 字段草案 | 不变量 |
|---|---|---|
| KnowledgeDocument | document_id、version、title、source_uri、content_hash、retrieved_at、published_at?、authority、license_ref、applies_to | 原始内容与加工版本可追溯；缺日期不得编造 |
| Chunk | chunk_id、document_id/version、section_locator、text_hash、text、tags、token_estimate | 可回到原文段落；切块不丢单位/条件/否定语义 |
| Skill | skill_id、version、content_hash、capabilities_required、applicable_tasks、contract_refs、methods、limitations | 系统批准版本；文本不能自发授予权限 |
| Recipe | recipe_id、version、parameter_schema、builder_id/version、assets、seed_policy、bounds_rule、target_support | 参数、工具与资源闭包固定，执行可回放 |
| AssetDefinition | asset_id、version、content_hash、kind、units、axes、pivot、bounds、geometry_refs、material_refs、collision_ref、lods、target_support、provenance_ref | 内容变更产生新版本；不能仅按名称复用 |
| AssetInstance | object_id、asset_id/version、transform、variant、overrides、lock_refs | 实例 ID 稳定，override 仅限声明字段 |
| LicenseRecord | license_id/expression、license_text_ref、source_uri、author、attribution、allowed_uses、redistribution_status、review_status | 保留证据，不从“免费”推断可再分发 |

大文件进入内容寻址 ArtifactStore；检索元数据和来源引用进入本地目录库。全文索引是可重建派生数据，不能成为唯一知识原件。AssetDefinition 的运行元数据与世界对资产的引用分离，使资源去重不影响实例锁和历史修订。

## 3. 内容接入与版本流程

1. 发现候选来源，记录来源地址、时间与授权来源类别；远程地址经过网络策略，禁止自动访问任意返回 URL。
2. 下载或读取到隔离区；限制压缩/解压大小、条目数、文件类型和递归深度。拒绝路径逃逸、链接逃逸、重复路径和伪装类型。
3. 保存原件摘要；文本解析、单位归一、几何转换和缩略图生成分别记录工具版本。失败不把部分数据登记为 ready。
4. 完成许可与资源闭包检查；依赖纹理、材质、网格、字体和必要说明全部可定位。资源依赖图禁止环或超限展开。
5. 建立适用能力标签和精确元数据；包络、实际尺寸、目标格式支持从解析器/校验器产生，不只信供应商描述。
6. 批量建立索引并发布不可变目录版本；正在运行的任务继续使用原目录版本，更新不覆盖其读取证据。

建议内容状态为 quarantined、ready、restricted、retired、rejected。restricted 表示已知使用范围受限，不等于恶意；retired 保留历史可解释性但不参与新推荐。资产被撤下时，新任务按策略拒绝使用，已有修订是否允许归档/导出依据留存许可记录，不静默替换内容。

## 4. 检索接口与排序

`knowledge.search(query, task_type, capability_versions, target_profile, filters, limit)` 返回 query_id、目录版本、片段 ID、来源、适用范围、匹配理由与排序分值。`assets.search()` 先按目标支持、尺寸、许可和资源预算过滤，再按语义标签、风格与匹配度排序。`recipes.get(id, version)` 按精确版本取回，不返回“最新版”替换已绑定依赖。

首版采用本地标签、元数据和关键词检索；支持中文分词/同义词映射的实际策略需用固定查询集评估。向量检索是可替换的召回插件，不能成为基础使用的必需云服务。向量分值不表示事实正确率，也不能覆盖精确过滤失败。

推荐检索顺序：任务/目标硬过滤 → 标题与标签匹配 → 正文召回 → 版本/来源评分 → 去重与多样性选择 → 截断到上下文预算。算法版本及排序参数随目录发布记录。对候选资产缺少尺寸或适用 profile 的情况，返回“不完整”及缺失字段，不按猜测值参与布局。

检索无结果返回明确空集和诊断，可调整查询或请求能力缺口处理；不得伪造来源、资产 ID 或相似配方。过期资料可以作为历史参考，但必须标注其版本限制；与当前 profile 冲突的片段不作为当前执行规则。

## 5. 上下文构造与依赖记录

上下文优先级为：当前用户需求和不可变约束 → 精确修订/对象事实 → 当前任务 scope 与工具能力 → 已接受依赖 → 最近真实诊断 → 相关 Skill → 有来源参考。每类设独立 token/字节上限，资源大体积数据只传引用，模型可按需查询。

ContextBundle 包含 context_id、task/version、base_revision、需求摘要引用、对象/空间查询回执、skill/version、chunk/hash、asset/version、tool/profile版本和裁剪说明。摘要必须保持必需项和硬约束，不得将其裁掉后继续执行。超过最小上下文能力时明确拒绝该任务或请求分解。

记录实际消费的知识与资源，而非把整个目录写入读集：知识变化失效依赖该版本的任务；仅搜索而未选中的资产不使所有场景失效。搜索目录版本、过滤条件和候选集合摘要仍应保存，以解释当时为何选择某资产。

模型/外部资料可能包含指令、安装脚本或要求忽略约束的文字。检索结果作为带类型的引用数据注入；只有系统批准 Skill 能描述工作方法，任何文本都不能越过网关权限。不能为了引用资料而把凭据、完整私人文件或无关历史发送给远端模型。

## 6. 配方和实例的复用边界

配方只展开显式参数，例如树冠尺寸、树干高度、叶片材料和 seed；不能悄悄减少树数量、移动营地或放宽道路净空。随机算法及 seed 固定，结果保存为 Artifact。新算法版本可生成新结果，但不修改已有修订资源。

同一配方可以生成多个共享网格的实例；变体参数与实例 ID 独立。修改单株树默认只创建该实例的新覆盖/资产变体，不改共享资产使整个森林变化。组级重采样必须声明替换范围、ID保留规则与锁处理；锁定实例不参与重采样。

外部可执行配方不是普通资产。首版仅启用内置白名单 builder；用户导入的配方数据经过 Schema 校验，不接受任意脚本。支持新的可执行扩展需要独立签名/信任、资源限制和安全评审，不由检索命中触发安装。

## 7. 许可、来源与供给链

许可元数据建议使用适用的 SPDX 标识/表达式并附原始许可文本；非标准条件保留原文引用和人工审查状态。SPDX 只规范标识，不自动判定具体资产能否用于项目或被打包再分发。[SPDX 官方许可信息说明](https://spdx.dev/learn/handling-license-info/)，访问 2026-11-11。

| 条件 | 运行策略 | 导出策略 |
|---|---|---|
| 明确可在允许范围使用并再分发 | 可进入 ready 目录 | 包含资源与所需署名/许可 |
| 可本地使用但不可再分发原件 | 标记 restricted，显示用途限制 | 阻断包含原资源的完整可移植包，给出缺口清单 |
| 来源或许可未知 | 不自动用于可交付世界 | 不以代理几何偷偷替换；需明确选择 |
| 包含必要署名/通知 | 将要求关联资产摘要 | 生成 attribution 清单并验证完整性 |
| 资源版本或摘要与声明不符 | 隔离并拒绝本次接入 | 不能沿用旧文件的审核结果 |

外部依赖清单包含资产、纹理、配方、转换器及其版本与摘要；软件依赖和内容资产分别管理。下载 TLS 只证明传输通道，不证明内容可信。签名可以证明发布者与内容完整性，不能替代文件解析、许可或几何检查。

## 8. 离线包与缓存

离线交付保存必需知识/Skill版本引用、配方、资产闭包、来源与许可清单。与世界重开直接相关的资产必须内嵌或在可验证本地资源库存在；远端 URL 不是完整可移植性的证明。可选参考文献可以保留链接，但标记未内嵌，不把其可达性当运行依赖。

缓存键包含资源内容摘要、解析/归一算法版本、profile、许可策略版本和查询条件。过期策略分别针对远程元数据、可再下载缓存和已接受修订依赖：历史引用资源不可因为缓存 TTL 到期删除。GC 以修订、活动候选、运行记录和显式保留根进行可达性扫描。

目录更新、许可状态变化和工具/profile升级触发明确的重新评估事件；不在后台改写世界。离线状态下可使用已验证本地资源，远程缺失返回 capability/resource unavailable。缓存命中必须保留原来源和版本，不能重新标记为当前在线核验。
